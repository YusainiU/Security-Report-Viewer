01 / Local scan

Run security scan

Use this option if the Linux account running this application has permission to read the required logs in /var/log (or the configured log directory). The scan runs on the host running this application, and reports are saved automatically.

Limited log access or sudo required? If the application cannot read the required logs, or you want to scan a different server, use the Download security scanner option below. Run the script manually on the target server with appropriate permissions, then upload the generated report. Do not run the web application as root. Unreadable logs may result in incomplete scan results.

02 / Standalone scanner

Download security scanner

Run the scanner manually on the Linux machine whose logs you want to analyse, including servers that require elevated permissions.

Download security-log-scan-v3.sh

How to run the scanner and upload a report
  1. Download the script. If scanning a remote server, securely transfer the script to that server and connect using SSH. For WSL, copy the downloaded file into your Linux home directory.
  2. Open a terminal on the target machine and change to the directory containing the downloaded script (for example, cd ~/Downloads if that is where you saved it).
  3. Review the script before executing it. Create a private report directory and run the scanner:
    chmod 700 security-log-scan-v3.sh
mkdir -p ~/security-reports
chmod 700 ~/security-reports
cd ~/security-reports
bash /absolute/path/to/security-log-scan-v3.sh
    Replace /absolute/path/to/ with the actual directory containing the script.
  4. If protected logs cannot be read, an authorised administrator may run the reviewed script with sudo instead:
    sudo /bin/bash /absolute/path/to/security-log-scan-v3.sh
    The report will be owned by root. To make only that report readable by your account, use the exact filename printed by the scanner:
    sudo chown "$(id -u):$(id -g)" -- ./security-report-EXACT-NAME.txt
chmod 600 ./security-report-EXACT-NAME.txt
    Replace the example filename with the actual generated filename. Never run the Rust web application as root.
  5. Optional: use --days 7 to filter supported timestamps, or --help for all options. Python 3 is required. Yearless syslog records are excluded from date-filtered scans and reported as unknown dates. Look for Report saved: in the terminal output. Transfer the generated text or JSON file securely to the computer running your browser if needed, then choose it in Upload a security report and click Analyse report.

Reports may contain sensitive log entries. Keep them private. Permission errors can mean incomplete coverage; zero matches do not establish that the server is safe.
